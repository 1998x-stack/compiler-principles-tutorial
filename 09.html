第9章 抽象语法树

大家好，我是你们的讲师。在上一章中，我们学会了用 ANTLR4 从文法定义自动生成解析器，并得到了完整的解析树（Parse Tree / CST）。解析树忠实地反映了文法的全部细节——包括每个括号、每个分隔符、每个关键字。但问题来了：对于编译器的后续阶段来说，这些细节中的大部分是噪声。

想想看，当你分析表达式 (1 + 2) * 3 时，你真的关心源代码中的那个左括号 '(' 和右括号 ')' 吗？不，你关心的是：这是一个乘法运算，左操作数是一个加法，右操作数是数字 3。括号只是为了在文法层面影响解析树的形状，但对语义分析、优化和代码生成来说，它的"任务"已经完成了。这就是为什么编译器在语法分析之后，会从 CST 构建出一个更简洁、更抽象的数据结构——抽象语法树（AST）。

核心概念：AST 提取了程序语义的"骨架"，去掉了那些纯语法性质的辅助节点（括号、分号、逗号分隔符等）。它只保留对后续阶段有意义的元素：运算符、操作数、语句类型、声明信息等。AST 的设计质量直接影响编译器的可维护性和后续优化能力，是编译器架构中最为关键的数据结构之一。

AST 与 CST 的关键区别

很多初学者会混淆 CST（具体语法树，即解析树）和 AST。两者的区别可以用一句话概括：CST 包含所有语法细节，AST 只包含语义要素。让我们用一个具体例子来说明：

对于表达式 a = 3 + 4 * 5;：

  • CST（解析树）包含：赋值语句节点、标识符 a、等号 =、加法 +、乘法 *、数字 3、4、5、分号 ;，以及文法引入的所有中间规则节点（如 expr、term、factor 等）。
  • AST 只包含：赋值节点（Assignment，左子=变量 a，右子=加法表达式）、加法节点（BinaryOp: +，左子=3，右子=乘法）、乘法节点（BinaryOp: *，左子=4，右子=5）。分号、等号、中间规则节点全部消失。
维度 CST（解析树） AST
节点数量 较多，包含文法中的每个规则和 token 较少，只保留语义要素
包含细节 括号、分隔符、关键字、中间规则 仅包含运算符、操作数和结构信息
文法依赖 紧密耦合于具体文法的写法 与文法解耦，反映语言语义结构
后续处理 通常不直接用于语义分析或代码生成 语义分析、优化、代码生成的主要输入

AST 节点设计

设计良好的 AST 是编译器成功的一半。不同的语言特性和编译需求会影响 AST 的具体设计，但有一些通用的设计原则可以遵循。

基类设计

大多数 AST 实现采用组合模式（Composite Pattern）——所有节点继承自一个公共基类，基类定义统一接口：

// AST 节点的公共基类
abstract class ASTNode {
    // 源码位置信息（所有节点都记录位置）
    SourceLocation location;

    // 虚方法：接受 Visitor（经典的 accept 方法）
    public abstract <T> T accept(ASTVisitor<T> visitor);

    // 子节点管理（可选，用于通用遍历）
    public abstract List<ASTNode> getChildren();
}

// 具体节点类型：表达式（抽象）
abstract class Expr extends ASTNode { }

// 具体节点类型：语句（抽象）
abstract class Stmt extends ASTNode { }

// 二元运算表达式
class BinaryExpr extends Expr {
    String operator;       // "+", "-", "*", "/", etc.
    Expr left, right;      // 左右子表达式

    @Override
    public <T> T accept(ASTVisitor<T> v) {
        return v.visitBinaryExpr(this);
    }
}

// 数值字面量
class NumberLiteral extends Expr {
    int value;

    @Override
    public <T> T accept(ASTVisitor<T> v) {
        return v.visitNumberLiteral(this);
    }
}

// 变量声明语句
class VarDeclStmt extends Stmt {
    String name;
    Type type;
    Expr initializer;

    @Override
    public <T> T accept(ASTVisitor<T> v) {
        return v.visitVarDeclStmt(this);
    }
}

节点类型分类

AST 节点通常按语义功能分为几个大类：

  • 表达式节点（Expr）：表示一个值的计算，如字面量、二元运算、函数调用、数组访问等。
  • 语句节点（Stmt）：表示一个动作，如赋值、if-else、while 循环、return、变量声明等。
  • 声明节点（Decl）：表示函数声明、类声明、模块声明等顶层结构。
  • 类型节点（Type）：表示类型信息，如 int、float、指针类型、数组类型等。

Visitor 模式遍历

有了 AST 之后，编译器的各个阶段（类型检查、优化、代码生成）都需要遍历这棵树。Visitor 模式是遍历 AST 的经典范式，它将算法与数据结构分离，让你可以为不同的任务编写不同的 Visitor，而无需修改 AST 节点的代码。

accept/dispatch 机制

Visitor 模式的核心是双重分发（Double Dispatch）：调用 node.accept(visitor) 时，具体调用 visitor 的哪个 visit 方法，是由 node 的实际类型决定的。这避免了繁琐的 instanceof 链：

// Visitor 接口定义
interface ASTVisitor<T> {
    T visitBinaryExpr(BinaryExpr node);
    T visitNumberLiteral(NumberLiteral node);
    T visitVarDeclStmt(VarDeclStmt node);
    T visitIfStmt(IfStmt node);
    T visitWhileStmt(WhileStmt node);
    // ... 为每种节点类型定义一个 visit 方法
}

// 具体的 Visitor：代码生成 —— 将 AST 输出为三地址码
class CodeGenVisitor implements ASTVisitor<String> {

    private int tempCounter = 0;
    private String newTemp() { return "t" + tempCounter++; }

    @Override
    public String visitBinaryExpr(BinaryExpr node) {
        String left = node.left.accept(this);   // 递归访问左子
        String right = node.right.accept(this); // 递归访问右子
        String result = newTemp();
        emit(result + " = " + left + " " + node.operator + " " + right);
        return result;
    }

    @Override
    public String visitNumberLiteral(NumberLiteral node) {
        return String.valueOf(node.value); // 直接返回数值字符串
    }

    private void emit(String code) {
        System.out.println(code);
    }
}

// 使用方式：只需要一行调用
ASTNode ast = parse(source);
ast.accept(new CodeGenVisitor());
// 输出示例：
// t0 = 3 + 4
// t1 = t0 * 5
设计思路：注意 visitBinaryExpr 中的递归调用 node.left.accept(this) 和 node.right.accept(this)——这正是 Visitor 模式中"手动控制遍历顺序"的精髓。如果我们需要前序遍历，就先访问左子再访问右子；如果需要后序遍历，先处理子节点再处理当前节点。对于求值器来说，我们需要的是后序遍历（先算子表达式，再用结果计算父表达式），因此 accept 调用放在 emit 之前。

避免 instanceof 链

如果没有 Visitor 模式，我们可能会写出这样的代码：

// 反例：使用 instanceof 链进行节点分派
// 这种代码难以维护、性能较差、且容易遗漏分支
void traverse(ASTNode node) {
    if (node instanceof BinaryExpr) {
        BinaryExpr b = (BinaryExpr) node;
        traverse(b.left);
        traverse(b.right);
        System.out.println("二元运算: " + b.operator);
    } else if (node instanceof NumberLiteral) {
        NumberLiteral n = (NumberLiteral) node;
        System.out.println("数字: " + n.value);
    } else if (node instanceof VarDeclStmt) {
        // ...
    }
    // 每增加一种节点类型，这里就要加一个 else-if 分支
    // 如果忘了加，编译器也不会报错，只会静默跳过！
}

使用 Visitor 模式后，如果你添加了新的 AST 节点类型，ASTVisitor 接口会强制要求你为它实现 visitXxx 方法——否则编译器会报错。这是编译期检查的力量。

源码位置追踪

在编译器中，"定位"能力至关重要。当用户写出有问题的代码时，编译器必须告诉他确切的位置。没有源码位置信息的 AST，就像没有经纬度的地图——毫无实用价值。

SourceLocation 设计

// 源码位置信息
class SourceLocation {
    String filename;        // 源文件名
    int line;               // 起始行号 (从1开始)
    int column;             // 起始列号 (从1开始)
    int length;             // token 或节点在源码中的长度

    // 友好的错误报告格式
    @Override
    public String toString() {
        return filename + ":" + line + ":" + column;
    }
}

// 在创建 AST 节点时保存位置信息
NumberLiteral num = new NumberLiteral(42);
num.location = new SourceLocation("test.c", 3, 8, 2);
// 表示 42 这个数字位于 test.c 的第3行第8列，长度为2个字符

错误报告精确定位

有了 SourceLocation，错误报告才能做到精确且友好：

// 语义分析中发现类型不匹配
class TypeChecker extends BaseVisitor<Type> {
    @Override
    public Type visitBinaryExpr(BinaryExpr node) {
        Type leftType = visit(node.left);
        Type rightType = visit(node.right);

        if (!leftType.equals(rightType)) {
            reportError(
                node.location,
                String.format(
                    "类型不匹配: 不能在 '%s' (%s) 和 '%s' (%s) 之间进行运算",
                    node.left, leftType,
                    node.right, rightType
                )
            );
        }
        // ...
    }
}

// 输出示例：
// test.c:3:8 错误: 类型不匹配: 不能在 'x' (int) 和 'y' (String) 之间进行运算
// 第3行:     int z = x + y;
//                    ^
// 注意：有了 line/column/length，我们甚至能在错误消息中画出指向线

实战：构建算术表达式 AST 与 Pretty-Printer

让我们将以上知识综合起来，为一个算术表达式语言构建完整的 AST 和一个漂亮的打印器（Pretty-Printer）。Pretty-Printer 是 AST 最经典的 Visitor 应用之一——它将 AST 还原为格式良好的源代码文本，常用于调试和代码重构。

// ============ AST 定义 ============
abstract class Expr {
    abstract <T> T accept(ExprVisitor<T> visitor);
}

class Num extends Expr {
    int value;
    Num(int value) { this.value = value; }
    <T> T accept(ExprVisitor<T> v) { return v.visitNum(this); }
}

class Add extends Expr {
    Expr left, right;
    Add(Expr left, Expr right) { this.left = left; this.right = right; }
    <T> T accept(ExprVisitor<T> v) { return v.visitAdd(this); }
}

class Sub extends Expr {
    Expr left, right;
    Sub(Expr left, Expr right) { this.left = left; this.right = right; }
    <T> T accept(ExprVisitor<T> v) { return v.visitSub(this); }
}

class Mul extends Expr {
    Expr left, right;
    Mul(Expr left, Expr right) { this.left = left; this.right = right; }
    <T> T accept(ExprVisitor<T> v) { return v.visitMul(this); }
}

// ============ Visitor 接口 ============
interface ExprVisitor<T> {
    T visitNum(Num node);
    T visitAdd(Add node);
    T visitSub(Sub node);
    T visitMul(Mul node);
}

// ============ Pretty-Printer ============
class PrettyPrinter implements ExprVisitor<String> {
    // 显示优先级：加法/减法为1，乘法为2
    private int parentPrec = 0;

    PrettyPrinter() { this.parentPrec = 0; }

    private PrettyPrinter(int prec) { this.parentPrec = prec; }

    @Override
    public String visitNum(Num node) {
        return Integer.toString(node.value);
    }

    @Override
    public String visitAdd(Add node) {
        return printBinOp(node.left, 1, "+", node.right, 1);
    }

    @Override
    public String visitSub(Sub node) {
        return printBinOp(node.left, 1, "-", node.right, 1);
    }

    @Override
    public String visitMul(Mul node) {
        return printBinOp(node.left, 2, "*", node.right, 2);
    }

    private String printBinOp(Expr left, int leftPrec,
                               String op, Expr right, int rightPrec) {
        String l = wrap(left, leftPrec, this.parentPrec);
        String r = wrap(right, rightPrec, this.parentPrec);
        return l + " " + op + " " + r;
    }

    private String wrap(Expr expr, int prec, int parentPrec) {
        String result = expr.accept(new PrettyPrinter(prec));
        // 如果子表达式的优先级低于父表达式，需要加括号
        if (prec < parentPrec) {
            return "(" + result + ")";
        }
        return result;
    }
}

// ============ 演示 ============
// 构造 AST: 1 + 2 * 3
//     (+)
//    /   \
//   1    (*)
//       /   \
//      2     3
Expr ast = new Add(
    new Num(1),
    new Mul(new Num(2), new Num(3))
);

PrettyPrinter pp = new PrettyPrinter();
System.out.println(ast.accept(pp));
// 输出: 1 + 2 * 3  (正确！乘法优先级高，没有多余的括号)

// 构造 AST: (1 + 2) * 3
//     (*)
//    /   \
//  (+)    3
//  / \
// 1   2
Expr ast2 = new Mul(
    new Add(new Num(1), new Num(2)),
    new Num(3)
);
System.out.println(ast2.accept(pp));
// 输出: (1 + 2) * 3  (正确！因为加法优先级低于乘法，自动插入了括号)
关键洞察：上面的 Pretty-Printer 中，prec（优先级参数）与 parentPrec 的比较是决定是否加括号的核心逻辑。当子表达式的优先级（如加法为1）低于父表达式（如乘法为2）时，就需要加括号。如果不需要考虑优先级（比如所有运算都用括号包裹），那么 Pretty-Printer 的实现会简单得多，但输出也会冗长得多。这个优先级感知的 Pretty-Printer 展示了 AST 遍历中的一个重要技巧：通过参数在父子节点之间传递上下文信息。
