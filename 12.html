第12章 LLVM IR入门

大家好，我是你们的讲师。上一章我们学习了中间表示的理论——三地址码、SSA 形式、控制流图与支配树。今天，我们要把这些理论与现实中的 IR 实现对应起来。而当今最成功、最广泛使用的 IR 实现，非 LLVM IR 莫属。

LLVM 项目最初由 Chris Lattner 在 2000 年作为其硕士论文工作启动，如今已经发展成为编译器基础设施的"事实标准"。Apple 的 Xcode 使用 LLVM，Android 的开发工具链使用 LLVM，Rust 编译器使用 LLVM，甚至 NVIDIA 的 CUDA 编译器也基于 LLVM。而 LLVM IR 正是这个庞大生态系统的"通用语言"——所有前端语言编译到 LLVM IR，所有优化在 LLVM IR 上进行，所有后端从 LLVM IR 生成目标代码。

为什么要学习 LLVM IR？因为它不只是一种 IR 的实现，更是一种工程化的 SSA 实践。LLVM IR 的设计非常精良——它有明确的类型系统、丰富的指令集、清晰的 SSA 约束，以及一整套工具链（优化器、汇编器、反汇编器、解释器）。学完本章以后，你将能够读懂 .ll 文件、用 Clang 生成 IR、用 opt 优化 IR、用 lli 解释执行 IR。这不仅加深对编译原理的理解，也是一项实用的工程技能。

LLVM IR 的三种形式

LLVM IR 有三种等价的形式，它们可以在不丢失信息的前提下相互转换：

形式 扩展名 用途
内存格式（In-Memory） — 编译器内部的核心表示，由 C++ 对象（Value、Instruction、BasicBlock 等）构成
Bitcode 格式 .bc 二进制编码的 IR，紧凑且加载快，用于链接时优化（LTO）和分发
文本格式 .ll 人类可读的 IR 文本，用于调试、教学、手动分析

三种形式的转换工具：

# .ll → .bc: 汇编（将文本格式转为二进制）
llvm-as input.ll -o output.bc

# .bc → .ll: 反汇编（将二进制格式转为文本）
llvm-dis input.bc -o output.ll

# .cpp → .ll: 用 Clang 编译 C/C++ 到 LLVM IR
clang -S -emit-llvm input.c -o output.ll

# .ll → .s: 将 LLVM IR 编译为目标架构的汇编
llc input.ll -o output.s

# .bc → 执行: 用 LLVM 解释器直接执行 bitcode
lli input.bc

类型系统详解

LLVM IR 是一个强类型的 IR——每条指令的操作数类型都必须是明确的且相容的。这是 LLVM IR 区别于许多学术 IR 的特点，也是它能在早期就发现大量错误的原因。

基础类型

; 整数类型（iN 表示 N 位整数）
i1      ; 1 位整数（布尔值，值为 0 或 1）
i8      ; 8 位整数（byte）
i32     ; 32 位整数（int）
i64     ; 64 位整数（long）

; 浮点类型
float   ; 32 位单精度浮点数（IEEE 754）
double  ; 64 位双精度浮点数（IEEE 754）
half    ; 16 位半精度浮点数

; 空类型
void    ; 无返回值函数的返回类型

复合类型

; 指针类型 — 指向某个类型的指针
i32*            ; 指向 32 位整数的指针
double*         ; 指向 double 的指针
i32**           ; 指向指针的指针（二级指针）

; 数组类型 — [长度 x 元素类型] （长度必须是常量）
[10 x i32]      ; 包含 10 个 i32 元素的数组
[5 x [3 x i8]]  ; 5x3 的二维 i8 数组

; 结构体类型 — 包含不同类型的字段（类似于 C 的 struct）
{ i32, i32 }        ; 包含两个 i32 字段的结构体
{ i8*, i32 }        ; 包含一个指针和一个整数的结构体

; Vector 类型 — 用于 SIMD 操作
<4 x i32>           ; 包含 4 个 i32 元素的 vector
<8 x float>         ; 包含 8 个 float 元素的 vector

; 标签类型 — 用于基本块的标识
label               ; 控制流目标

核心指令

让我们通过一个完整的例子来学习 LLVM IR 的核心指令集。下面的 LLVM IR 代码实现了一个计算阶乘的函数：

; factorial.ll — 计算 n! 的 LLVM IR 实现
; 定义一个名为 factorial 的函数，接受 i32 参数，返回 i32
define i32 @factorial(i32 %n) {
entry:
    ; === 比较 n 是否大于 1 ===
    ; icmp: 整数比较指令
    ; sgt: signed greater than (有符号大于)
    %cond = icmp sgt i32 %n, 1

    ; br: 分支指令
    ; br i1 %cond, label %then, label %else
    ; 如果 %cond 为 true，跳转到 then 基本块；否则跳转到 else
    br i1 %cond, label %recursive, label %base

base:
    ; 基本情况：如果 n <= 1，返回 1
    ret i32 1

recursive:
    ; === 递归情况：n * factorial(n - 1) ===

    ; sub: 减法指令
    %n_minus_1 = sub i32 %n, 1

    ; call: 函数调用指令
    %sub_result = call i32 @factorial(i32 %n_minus_1)

    ; mul: 乘法指令
    %result = mul i32 %n, %sub_result

    ; ret: 返回指令
    ret i32 %result
}

内存操作指令

LLVM IR 是 SSA 形式——每个变量只能赋值一次。那么如何处理可变变量呢？答案是使用 alloca + load/store：

; 使用 alloca 在栈上分配变量
define i32 @example() {
    ; alloca: 在栈帧上分配空间，返回指向该空间的指针
    %x_ptr = alloca i32      ; 分配一个 i32 的空间
    %y_ptr = alloca i32

    ; store: 将值写入指针指向的内存
    store i32 42, i32* %x_ptr   ; *x_ptr = 42

    ; load: 从指针指向的内存读取值
    %x_val = load i32, i32* %x_ptr  ; %x_val = *x_ptr

    %result = add i32 %x_val, 1
    ret i32 %result
}
关键理解：alloca 指令是 LLVM IR 中唯一打破 SSA 约束的方式——因为通过 store 可以多次向同一个内存位置写入不同的值，然后通过 load 读取。但编译器不鼓励大量使用 alloca，因为这会阻碍优化。优化器会尽量将 alloca/load/store 模式转化为 SSA 值（通过 mem2reg pass），这样就可以在 SSA 形式上进行更高效的数据流分析。

getelementptr 指令

getelementptr（简称 GEP）是 LLVM IR 中最令人困惑但也最强大的指令。它用于计算数组元素或结构体字段的地址偏移，但不访问内存：

; 定义: %arr 是一个指向 [10 x i32] 的指针
%arr_ptr = alloca [10 x i32]

; 获取 arr[3] 的地址
; GEP 的参数: (基础指针, 偏移索引...)
; 第一个偏移索引 "0" 表示"解引用"指针本身
; 第二个偏移索引 "3" 表示数组中的第3个元素
%elem_ptr = getelementptr [10 x i32], [10 x i32]* %arr_ptr, i32 0, i32 3

; 等价于 C 代码中的: &arr[3]

; 结构体 GEP:
; %person_ptr 是 { i8*, i32 }*   (name 和 age)
%name_ptr = getelementptr { i8*, i32 }, { i8*, i32 }* %person_ptr, i32 0, i32 0
; 取第 0 个字段 (name) 的指针
GEP 常见陷阱：初学者最容易犯的错误是认为 GEP 会访问内存！实际上，GEP 只做地址计算，不产生内存访问。如果你想读取计算结果，需要在 GEP 之后加一条 load 指令。另外，GEP 的索引语义与 C 的数组索引不同——GEP 的第一个索引总是解引用顶层指针，第二个索引才访问第一个维度。把 GEP 理解为"计算一个子对象地址的数学运算"而非"指针算术"，会更容易掌握。

Phi 指令

LLVM IR 原生支持 SSA 的 phi 指令：

define i32 @max(i32 %a, i32 %b) {
entry:
    %cond = icmp sgt i32 %a, %b    ; a > b ?
    br i1 %cond, label %then, label %else

then:
    br label %merge

else:
    br label %merge

merge:
    ; phi 指令：根据前驱基本块选择值
    ; 如果从 then 块来，选择 %a
    ; 如果从 else 块来，选择 %b
    %result = phi i32 [ %a, %then ], [ %b, %else ]
    ret i32 %result
}

用 Clang 生成 IR 实战

理论知识够了，让我们用实际的 Rust 代码（其实等价于 C/C++，用 Clang）来验证 LLVM IR：

第一步：编写源代码

// example.c
#include <stdio.h>

int add(int x, int y) {
    return x + y;
}

int main() {
    int a = 10;
    int b = 20;
    int c = add(a, b);
    printf("Result: %d\n", c);
    return 0;
}

第二步：生成 LLVM IR

# -S: 生成文本格式的汇编/IR
# -emit-llvm: 输出 LLVM IR 而不是机器汇编
# -O0: 不优化，生成最"忠实"于源码的 IR
clang -S -emit-llvm -O0 example.c -o example.ll

# 也可以用 -O2 看看优化后的 IR 有多简洁
clang -S -emit-llvm -O2 example.c -o example_opt.ll

第三步：观察和优化 IR

# 查看生成的 IR
cat example.ll

# 使用 opt 工具运行优化 pass
# -O2: 应用全部的 -O2 级别优化
opt -O2 example.ll -S -o example_opt.ll

# 查看优化后的 IR，对比差异
diff <(grep -v '^;' example.ll) <(grep -v '^;' example_opt.ll)

# 查看可用的优化 pass 列表
opt -help | grep "pass"

第四步：直接解释执行 IR

# lli (LLVM Interpreter) 可以直接执行 IR 或 bitcode
lli example.ll
# 输出: Result: 30

# 也支持执行 bitcode
llvm-as example.ll -o example.bc
lli example.bc
# 输出: Result: 30
动手练习：尝试修改 example.c，添加循环、指针、结构体等特性，然后比较 -O0 和 -O2 生成的 LLVM IR。你会惊讶地发现 -O2 生成的 IR 代码量通常比 -O0 少 5-10 倍——循环被展开、常量被折叠、死代码被消除、甚至整个函数调用被内联替换。在 IR 层面观察不同优化级别的效果，是理解编译器优化最直观的方式。

LLVM 工具链一览

工具 功能 典型用法
clang C/C++/ObjC 前端，编译到 LLVM IR clang -S -emit-llvm foo.c
opt LLVM IR 优化器，运行优化 pass opt -O2 foo.ll -S -o foo_opt.ll
llc LLVM IR → 目标汇编的静态编译器 llc foo.ll -o foo.s -march=x86-64
lli LLVM IR 解释器/JIT 编译器 lli foo.ll
llvm-as LLVM 汇编器（.ll → .bc） llvm-as foo.ll
llvm-dis LLVM 反汇编器（.bc → .ll） llvm-dis foo.bc
llvm-link 多个 .bc 文件链接为一个 llvm-link a.bc b.bc -o c.bc

本章小结

本章我们学习了 LLVM IR 的核心知识：三种表示形式的相互转换、强类型系统的设计（从 i1 到结构体指针）、核心指令集的使用（load/store/br/phi/call/GEP 等），以及通过 Clang 从 C 代码生成 LLVM IR 的完整工作流。LLVM IR 不仅是理论研究中的"SSA IR"，更是一个工业级的、可实际操作的工具——你现在已经可以手写 .ll 文件，然后用 lli 执行它了。
